# 09 実装・ビルド・公開手順

## 1. 必要な環境

| 用途 | 必要なもの |
|---|---|
| ビルド・静的書き出し | Node.js 18以上（npmパッケージの追加は不要） |
| プレビュー | 任意の静的サーバー（例：`python3 -m http.server`） |
| サムネイル生成（任意） | Python 3、Pillow（`pip install pillow`）、Noto Sans CJK／Noto Serif CJK の .ttc フォント |
| 記事の取り込み（任意） | Python 3 |

PHP、データベース、サーバー側の処理は使いません。

## 2. ソースの構成（source/）

```
source/
├─ package.json
├─ src/
│   ├─ bundle.src.js      基本部品・サイトデータ・動き（約800行）
│   ├─ bundle.more.js     トップ拡張・連載・質問箱・キャンペーン（約200行）
│   ├─ bundle.column.js   コラム一式・サイトカテゴリのハブ（約280行）
│   ├─ sotorino.css       全スタイル（約120KB、トークンは var() で参照）
│   ├─ tokens.json        デザイントークン（正本）
│   └─ sotorino.d.ts      部品の引数の型定義
├─ content/
│   └─ columns.json       コラム記事150本（正本）
├─ public/
│   └─ index.html         プレビュー版の入口（ルーター・画像キー対応表）
└─ scripts/
    ├─ build.mjs          src＋content＋images → public/
    ├─ ssg.cjs            public/ → dist/（公開用の静的HTML）
    ├─ thumbs.py          コラムのサムネイル生成 → images/04_column-thumbnails/
    └─ import-articles.py 入稿JSONを content/columns.json に取り込む
```

`bundle.*.js` は4つで1つのスクリプトです。`build.mjs` が `bundle.src.js` → `bundle.more.js` → `bundle.column.js` → `bundle.pages.js`（固定ページ・ガイド記事・フォーム・タグ・用語集・ルーティング）の順に連結して `public/sotorino.js` を作ります。この順番は変えないでください（後のファイルが前のファイルの関数を使う）。

## 3. ビルドの流れ

```
                 ┌────────────── build.mjs ──────────────┐
src/bundle.*.js ─┤ 連結 → public/sotorino.js              │
src/sotorino.css ┤ コピー → public/sotorino.css           │
src/tokens.json ─┤ 変換 → public/tokens.css               │
content/columns.json ─ 必要項目だけ → public/columns.js  │
content/pages.json ── → public/pages.js、検索索引 public/search.js │
../images/01〜03 ┤ フラットにコピー → public/img/         │
../images/04 ────┘ → public/img/col/                       │
                                                           
public/ ──────────── ssg.cjs ────────→ dist/
  （Node上で各ページの関数を呼び、HTMLを書き出す）
  dist/index.html, dist/column/{slug}/index.html …（196ページ）
  dist/assets/{sotorino.css, sotorino.js, tokens.css}
  dist/img/…
  dist/sitemap.xml, dist/robots.txt
```

コマンド：

```bash
cd source
npm run build        # = node scripts/build.mjs
npm run ssg          # = build ＋ node scripts/ssg.cjs
npm run serve        # public/ をプレビュー（http://localhost:8080/index.html）
npm run serve:dist   # dist/ を確認（http://localhost:8081/）
```

環境変数：

| 変数 | 既定値 | 用途 |
|---|---|---|
| `SITE_ORIGIN` | https://sotorino.jp | canonical・OGP・構造化データ・サイトマップのドメイン |
| `SOTORINO_IMAGES` | `../images` | 画像フォルダの場所 |
| `AFFILIATE` | （なし） | `1` にすると商品ページ・商品カードを公開（承認後） |
| `FORM_ENDPOINT` | （なし） | フォームの送信先URL（12章） |
| `FONT_DIR` | /usr/share/fonts/opentype/noto | サムネイル生成のフォント |

```bash
SITE_ORIGIN=https://www.example.com npm run ssg
```

## 4. 静的ページの中身

1ページの構成（`ssg.cjs` の `page()`）：

```html
<!doctype html><html lang="ja"><head>
  <meta charset="utf-8"><meta name="viewport" …>
  <title>…｜SOTORINO</title><meta name="description" …><link rel="canonical" …>
  <link rel="prev/next" …>（一覧のみ）
  <meta property="og:…">（記事は og:image と twitter:card も）
  <link rel="stylesheet" href="/assets/tokens.css"><link rel="stylesheet" href="/assets/sotorino.css">
  <script type="application/ld+json">[…]</script>
</head><body>
  …部品が出力したページ全体のHTML（本文入り）…
  <script src="/assets/sotorino.js" defer></script>
  <script>DOMContentLoaded で Sotorino.config.base=''; Sotorino.mount(document)</script>
</body></html>
```

- JSが読み込まれる前から本文・リンク・画像はすべて表示されます。JSは動き（スライダー、タブ、検索候補、目次、お気に入り、ドロワー）を後から結び付けるだけです。
- Webフォントは `sotorino.css` の先頭で Google Fonts を読み込んでいます。

### 書き出し対象を増やす

`ssg.cjs` の `extra` 配列に `[URL, HTML, title, description, 構造化データ, priority]` を1行足します。

```js
['/about/', S.AboutPage(), '運営者情報｜SOTORINO', '…', [bc([['HOME','/'],['運営者情報']])], '0.3'],
```

## 5. 公開（デプロイ）

`dist/` の中身をそのまま公開ディレクトリに置くだけです。

| サービス | 設定 |
|---|---|
| Netlify / Cloudflare Pages / Vercel | ビルドコマンド `cd source && npm run ssg`、公開ディレクトリ `source/dist`。画像フォルダ `images/` も同じリポジトリに入れる |
| レンタルサーバー（さくら・エックスサーバー等） | `dist/` の中身をFTPで `public_html/` などへアップロード |
| Amazon S3＋CloudFront | 静的ウェブサイトホスティング。インデックスドキュメント `index.html` |

推奨のサーバー設定：

- `https` に統一し、`www` あり／なしのどちらかに301で寄せる
- 末尾スラッシュなし（`/column/abc`）→ あり（`/column/abc/`）へ301
- `/assets/*` と `/img/*` は長期キャッシュ（例：`Cache-Control: public, max-age=31536000`）。ファイルを差し替えたらファイル名を変えるか `?v=` を付ける
- HTMLは短いキャッシュ（例：`max-age=300`）
- 404ページ（`404.html`）を用意する（未作成。11 参照）
- gzip または brotli 圧縮を有効に

公開後：Google Search Console にドメインを登録し、`/sitemap.xml` を送信します。

## 6. 公開前の確認項目

| 確認 | 方法 | 基準 |
|---|---|---|
| 横スクロールが出ない | 390px・768px・1280pxで全テンプレートを表示 | `document.documentElement.scrollWidth === innerWidth` |
| 画像の読み込み失敗がない | ブラウザの開発者ツール（Network） | 404なし |
| JSエラーがない | Console | エラー0 |
| 本文がHTMLにある | JSを無効にして記事を表示 | 本文・目次・FAQが読める |
| 構造化データ | Googleのリッチリザルトテスト | Article／BreadcrumbList／FAQPage がエラーなし |
| title・description | 全ページ | 重複なし、空なし |
| 内部リンク切れ | クローラー（Screaming Frog 等）や簡易スクリプト | 11 の未作成ページを作るか、リンクを外す |
| コントラスト | Lighthouse のアクセシビリティ | 90点以上 |
| 表示速度 | Lighthouse（モバイル） | LCP 2.5秒以内を目標 |
| PR表記 | 商品・相談バナー | すべて「PR」表記と `rel="sponsored"` |

このキットの作成時点で、全テンプレートのPC（1280px）・スマホ（390px）表示で横スクロール0、JSエラー0、画像の読み込み失敗0を確認しています。

## 7. ほかの技術に移すときの指針

| 移行先 | やり方 |
|---|---|
| Astro（推奨） | `src/bundle.*.js` をそのまま読み込み、各 `.astro` ページで `set:html={S.ColumnArticlePage(slug)}` を出力。`getStaticPaths` は `columns.json` から作る |
| Next.js（SSG） | 同じく `generateStaticParams`＋`dangerouslySetInnerHTML`。徐々にReact部品へ置き換える場合も、HTML構造とクラス名は 05 と screenshots/ に合わせる |
| ヘッドレスCMS（microCMS、Contentful 等） | `columns.json` の項目をそのままスキーマにする（07 の表）。本文はリッチテキストではなくHTML欄にして、見出しの接頭語ルールを守る |
| WordPress | PHP不可の要件があるため、WordPressは管理画面としてだけ使い、REST APIから記事を取得して静的書き出しする構成にする |

どの方法でも、`sotorino.css` と `tokens.css` はそのまま使えます。

## 補足（2026年11月5日）お問い合わせ・PRバナー・アクセス解析

### フォーム（すべて同じメールに届く）
- お問い合わせ・見積もり依頼・カタログ請求・秋のキャンペーン応募・人工芝サンプル申込みの5つのフォームは、FormSubmit（無料の外部送信サービス）を通じて takaokashinnosuke01@gmail.com に届きます。送信先は `bundle.pages.js` の `S.config.formEndpoint` で設定しています。
- 件名はフォームごとに分けています（`pages.json` の `form.subject`）。例：「【SOTORINO】サイトへのお問い合わせ」「【SOTORINO】外構工事の見積もり依頼」。届いたメールに返信すると、入力されたメールアドレスに返信できます。
- **公開後に最初の1回だけ有効化が必要です。** 公開したサイトのフォームから一度テスト送信すると、FormSubmit から「Activate Form」のメールが届きます。メール内のボタンを押すと有効になり、それ以降の送信がそのまま届きます。
- 有効化のあとに届く英数字の文字列に送信先を差し替えると、HTML上にメールアドレスが出なくなり、迷惑メールを減らせます（`https://formsubmit.co/ajax/英数字`）。

### PRバナー（タップすると準備中ページへ）
- 「理想の外構をプロとつくる」「DIYで叶える理想の庭」のPRバナーは、タップすると `/preparing/`（このサービスは準備中です）に移ります。このページは検索に載らない設定（noindex）で、サイトマップにも入りません。
- 送客やアフィリエイトの準備が整ったら、`PR_READY=1 npm run ssg` で書き出すと、本来のリンク先（rel="sponsored" 付き）に戻ります。

### Googleアナリティクス・サーチコンソール
- `content/site.json` の `gaId` に、GA4の測定ID（G-から始まる）を入れて書き出すと、全ページに計測タグが入ります。環境変数 `GA_ID=G-XXXX` でも指定できます。
- アナリティクスは、サーチコンソールに登録していなくても使えます。
- サーチコンソールを「HTMLタグ」で確認する場合は、`gscVerification` に content の値を入れて書き出します。ドメインで確認する場合（DNS）は不要です。
- プライバシーポリシーには、Googleアナリティクスの利用とFormSubmitの利用を記載済みです。

### 人気記事ランキング
- アクセス解析の実データが入るまでは、順位を付けずに「編集部のおすすめ」として表示しています（`S.config.rankingLive` が false のとき）。GA4の数字で `S.data.ranking` を更新したら、`S.config.rankingLive = true` にすると順位付きのランキング表示に戻ります。
